## 2025-02-28 - IPC URL Parser Differential Vulnerability
**Vulnerability:** In `src/background.js`, `message.url` was validated using `new URL()` to check the protocol, but the original, un-normalized string (`message.url`) was passed to `browser.downloads.download()`. This could lead to a parser differential vulnerability where the validation parser evaluates a URL differently than the execution engine. Furthermore, IPC messages were missing type validation (`typeof message === 'object'`), which could crash the background service worker if malformed messages were sent.
**Learning:** Checking a property and then using the original raw string instead of the sanitized/normalized property creates a bypass vector. Additionally, always assume IPC messages (even from trusted content scripts) can be spoofed or malformed by a compromised context.
**Prevention:** Always use the normalized output (e.g., `urlObj.href`) of validation functions at the trust boundary instead of the raw input. Implement robust type checking (`typeof message === 'object'`, `Array.isArray()`) for all incoming IPC payloads.
